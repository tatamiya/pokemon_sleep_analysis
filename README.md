# Pokémon Sleep 食材パターン分析

Pokémon Sleep の食材パターンについて、
個人で収集したデータを用いて出現確率や時間依存性を調べるプロジェクト。

分析は R / Quarto で行い、
分析結果をもとに note 向けの記事を作成する。

分析コード、固定した入力データ、詳細な計算結果を公開できるよう、
Quartoのウェブサイトとしても構成している。

## 分析ファイル

### `analysis/01_probability.qmd`

食材パターンの累積的な出現確率について調べる。

主な問い：

- 6パターンの比率は通説上の 1:1:1:2:2:2 と整合するか
- 2枠目の A:B は 1:2 と整合するか
- 3枠目の A:B:C は 1:1:1 と整合するか
- 2枠目と3枠目は独立とみなせるか
- 各確率はどの程度と推定されるか

頻度論的な検定に加え、
Dirichlet分布・Beta分布を用いたベイズ推定も行う。

現在の第1記事に対応する分析。

### `analysis/02_slot2_time.qmd`

2枠目Aの出現確率の時間変化を調べる。

`01_probability.qmd` では、
全期間をまとめると2枠目Aの出現割合が通説上の 1/3 より低いという結果が得られた。

一方、時系列で見ると、
初期から一貫して低かったわけではなく、
ある時期以降にAが出にくくなったようにも見える。

そこで、

- 出現確率は時間を通じて一定なのか
- 一定確率モデルに比べ、未知の1変化点を持つモデルはデータを明確によく説明するか
- 時間とともに滑らかに変化した可能性はあるか
- 現在の個体数と検定方法で、どの程度の変化を検出できるか

を調べる。

Part 2では「一定の未知確率」と「未知の時点で1回変化する確率」の比較を主分析とし、
滑らかな時間変化は補足的に扱う。

### `analysis/archive/`

これまでに行った探索的分析を保存する。

最新の分析と整合していることを確認する。

## 今後の記事候補

### 6パターンの時間変化

2枠目A/Bだけでは見えない変化が、6パターンの内訳にあるかを調べる。
ゲーム上特に関心の高いAAAについては、

特に、

\[
P(AAA)
=
P(\text{2枠目}=A)
P(\text{3枠目}=A\mid\text{2枠目}=A)
\]

と分解し、
AAAの増減がどの要素によって生じているかを見る。

さらに、短期的な偏りが単なるランダムなムラなのか、
少なかったパターンがその後に出やすくなるような履歴依存があるのかを区別して調べる。

### ランダム性・履歴依存性

各抽選が独立な固定確率のランダム抽選とみなせるかを調べる。

候補となるテーマ：

- 累積偏差
- 過分散・過小分散
- 週単位の変動
- ラグ依存
- 帳尻合わせ・バランシング
- 有限記憶モデル

## データ

記事と公開分析では、次の固定データを使用する。

```text
data/ingredient_patterns_2025-11-16_2026-09-05.csv
```

このCSVには、2025-11-16から2026-09-05までの360個体について、
日付、ポケモン名、食材パターンの情報を収録している。
列の説明は `data/README.md` を参照すること。

元データはGoogle Sheets上で継続的に更新しているが、
分析ファイルは直接シートを読まず、固定CSVを読み込む。
このため、シートの更新やGoogleアカウントの認証によって、
公開済み記事の結果が変わることはない。

主なデータフレーム：

- `df_org`: 読み込んだ固定公開データ
- `df`: 収集開始後かつ3食材種のみ
- `df2`: 収集開始後。2枠目の分析では2食材種も含める

したがって、
2枠目の分析と3枠目・6パターンの分析では
サンプルサイズが異なる場合がある。

Google Sheetsから固定CSVを作り直す方法は、
`data/README.md` と `scripts/update_data_snapshot.R` に記載している。

## 分析の再実行

作成時の主な実行環境は次のとおり。

```text
R 4.3.1
Quarto 1.9.38
```

パッケージのバージョンは `renv.lock` に記録する。
リポジトリを取得した後、プロジェクトのルートで次を実行する。

```r
install.packages("renv")
renv::restore()
```

分析サイト全体の生成：

```sh
quarto render
```

ローカルでの確認：

```sh
quarto preview
```

生成物は `_site/` に出力され、Git管理には含めない。

## 公開

GitHubリポジトリを設定した後、Quartoの分析サイトは
GitHub Pagesへ次のコマンドで公開できる。

```sh
quarto publish gh-pages
```

記事を公開した時点のコードとデータにはGitタグを付け、
どの版が各記事に対応するか分かるようにする。

## 基本的な作業の流れ

1. RStudio / Quarto で分析する
2. 分析結果を確認する
3. 必要に応じて `ANALYSIS_SUMMARY.md` を更新する
4. `article/` で記事を書く
5. 分析結果と記事中の数値・表現を照合する

`_site/` は Quarto の生成物であり、Git管理しない。
